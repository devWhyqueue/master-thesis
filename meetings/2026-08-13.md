## Extended taxonomy of mitigation signals

To support this broader perspective, I introduced a new taxonomy in the methods report. Instead of characterizing methods mainly by how they address class frequency, the taxonomy asks **which signal a mitigation method uses to determine that a class or example needs additional support**.

| Signal         | What it describes                                                            | Representative quantities                                                 |
| -------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **Prevalence** | Relative share of a class compared with the remaining classes                | Class prior $\pi_c$, support rank, imbalance ratio $\rho$                 |
| **Evidence**   | Absolute amount of independent observations available for a class            | $n_c$, distinct slides/patients, effective support $N_{\mathrm{eff},c}$   |
| **Difficulty** | How difficult a class or example is to classify under a fixed representation | Loss, predicted confidence $p_y$, decision margin, class difficulty $d_c$ |
| **Coverage**   | How well the observed samples span the within-class variation                | Manifold coverage $\mathrm{cov}_c$, effective rank of the class spectrum  |

This separates **relative frequency (prevalence)** from **absolute evidence**, while additionally accounting for **classification difficulty** and **within-class coverage**.

## Planned extension of the benchmark

The current method set is strongest on prevalence-aware mitigation. I am therefore researching a **small, manageable set of additional methods** that explicitly address currently underrepresented dimensions, particularly:

* **Difficulty-aware methods:** methods that give more attention to difficult classes or individual samples.
* **Coverage-aware methods:** methods that aim to compensate for insufficient representation of the within-class distribution.
* Potentially further **evidence-aware methods** that distinguish limited absolute support from relative class imbalance.

The most suitable candidates will then be integrated into the existing controlled benchmark.

## Why broaden the scope?

The goal is to create a clearer path from the empirical benchmark toward a **new mitigation method or an adaptation/improvement of an existing method**.

The intended progression is:

**1. Identify relevant performance-affecting dimensions in CPath data**
$\rightarrow$ prevalence, evidence, difficulty, and coverage.

**2. Understand existing mitigation methods as functions of these signals**
$\rightarrow$ determine which dimensions different methods exploit and under which data conditions they work.

**3. Analyze these relationships in controlled benchmark experiments**
$\rightarrow$ relate method performance to measured properties of the training data.

**4. Derive a method formulation or adaptation from these findings**
$\rightarrow$ develop a mitigation strategy that uses the relevant signals more explicitly or combines them more effectively.

This reframing should move the thesis beyond asking *“Which class-imbalance method performs best?”* toward the more general question:

> **Which properties make a class difficult to learn in CPath, and how should a mitigation method respond to them?**
